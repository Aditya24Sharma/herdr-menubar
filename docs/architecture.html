Herdr Menu Bar

How the menu bar app is put together

A small macOS app that watches every coding agent running inside Herdr and puts their state in your menu bar. This page explains the moving parts, why they are arranged this way, and what we ruled out.

1 — The pieces

Three programs, one socket

Herdr is already two programs: a server that quietly owns all your terminals, and a client that draws them in Ghostty. Our menu bar app is a third, separate program. It never touches your terminals directly — it only talks to the server.

They talk over a Unix socket, which is just a file on disk that two programs use like a phone line. Ours lives at ~/.config/herdr/herdr.sock.

2 — Staying up to date

One thing is pushed, one thing is pulled

The app keeps a list of agents in memory. Two different mechanisms keep that list honest, and they do different jobs.

That last point is the reason for the whole arrangement. Herdr will push “this agent changed state” only for a specific pane you named up front. So when panes appear or vanish, the app has to notice and re-subscribe.

3 — The trap we hit

Why we don’t listen for “a pane was created”

Herdr does offer an event for panes appearing. Using it seems obvious, and it broke badly. When you subscribe, Herdr first replays its stored history of the last 512 events, so a brand-new listener can catch up. Those replayed events look exactly like fresh ones.

The fix was to stop listening for those events entirely and compare snapshots instead. A snapshot describes what is true now, so re-reading it twice is harmless. An event says something happened, which is only safe if you know you haven’t already seen it.

We also dropped a second event, pane.updated, for a plainer reason: it fires about ten times a second while agents work, because their terminal titles animate.

4 — Clicking an agent

Jumping to a pane takes two separate steps

Herdr can move focus between panes, but it has no idea your terminal window is buried behind a browser. Those are two different problems, solved two different ways.

Finding the right window

Step 2 has a wrinkle: the app has to work out which application is hosting Herdr. It does that by walking up the family tree of running programs until it finds one macOS recognises as a real app. Shells and helpers have no app identity; Ghostty does. 

herdr        the client — no app identity
└─ zsh       no app identity
   └─ login  no app identity
      └─ Ghostty  ← first real app: this is the window to raise

This is why the app works if you switch to iTerm or Kitty tomorrow — it never hard-codes a terminal name, it just climbs until something answers.

5 — Notifications

Three ways to get your attention, tried in order

macOS only gives the good notification system to apps signed with a paid Apple developer certificate. Ours is built on your machine, so it falls back. The app tries each option and uses the first that works.

  1. 01 Apple’s own notifications Proper banner with a Jump to pane button. Needs a paid developer certificate, so it is currently unavailable — it will start working on its own if the app is ever signed.
  2. 02 terminal-notifier A small signed helper you can install with brew install terminal-notifier. Clicking the banner still jumps you to the pane. This is the one worth having.
  3. 03 A plain AppleScript banner Always works, but the notification is credited to Script Editor and clicking it does nothing. This is what you get today.

Herdr itself uses the same last two fallbacks, so installing terminal-notifier improves both.

6 — The code

Which file does what

Ten small Swift files. Each one has a single job.

HerdrSocket
Talks to the socket. Sends a line of JSON, reads lines back.
HerdrModels
What an agent, a workspace and a state are.
HerdrMonitor
The brain. Holds the agent list, runs the push and pull described above.
Jumper
The two-step jump, including the walk up the process tree.
Notifier
The three notification tiers.
Settings
Your toggles, and the launch-at-login switch.
MenuContent
The dropdown panel — agents grouped by workspace.
StatusIcon
Draws the robot head and the state dot, by hand.
HerdrMenuBarApp
Starts everything and puts the icon in the menu bar.
Log
Debug output, off unless you ask for it.

7 — Decisions

The choices worth remembering

Snapshots, not pane events
Events get replayed and cause an endless loop. A snapshot is safe to read twice.
Status pushed, panes polled
The thing you care about is instant. The slow five-second check is only for bookkeeping.
Climb the process tree
Finds the real terminal without hard-coding a list of terminal apps.
A hand-drawn robot
macOS ships no robot icon, so the head is drawn in code. That also lets the state dot sit on its corner.
The head stays neutral
Only the dot carries colour, so the icon looks at home next to the system icons instead of shouting.
State without words
A spinner, a colour and a faded row say it faster than a label, and the width goes to names instead. Blocked is drawn larger too, so red is not the only thing separating it from green.
Short lists don’t scroll
A scrolling box has no natural height, which once collapsed the whole panel to nothing.
